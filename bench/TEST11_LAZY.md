# Test 11: глобально подвижные координаты и ленивые ограничения

Полный код: `bench/solve_test11_lazy.py`. Зависимости уже есть в
`target/solver11-deps`. Скрипт использует проверенные `load_test` и `validate`
из `bench/inspect_test11_exact.py`.

**Статус:** это новый решатель поиска, а не найденный план 20760. В пробах
ранних редакций решения 20760 не получено. Последняя редакция подготовлена
без вычислительного запуска по просьбе пользователя. Гарантированного
времени нахождения решения для этой задачи нет.

## Математическая модель

У каждой из 2487 суффиксных труб есть переменная `y_i`. Первые 4006 координат
фиксированы точно как в `candidate-best15.txt`. Для каждой переменной
вычисляется точное объединение допустимых целочисленных диапазонов:

```
D_i = [0,H-len_i] \ union_j [y_j-len_i+1, y_j+len_j-1]
```

В объединение входят только префиксные `j`, пересекающие трубу `i` по
времени. Координаты других суффиксных труб в домены не вшиваются.

По исходному допустимому плану строится граф вертикального порядка.
На каждом элементарном интервале времени достаточно связать соседние
активные суффиксные трубы снизу вверх. Транзитивность этих связей задаёт
порядок любой одновременно активной пары. Для этого теста исходный граф
содержит 5909 связей.

Часть связей сохраняется как временные предположения:

```
keep_ij => y_i + len_i <= y_j
```

При доказанном INFEASIBLE CP-SAT возвращает достаточное UNSAT-ядро
предположений. Выбранные связи из ядра делаются обратимыми:

```
b_ij       => y_i + len_i <= y_j
not b_ij   => y_j + len_j <= y_i
```

Снятие связи не фиксирует координату и не удаляет трубу. Координаты могут
меняться по всему суффиксу, в том числе в длинной цепочке малых сдвигов.

После снятия связей транзитивное покрытие может перестать обеспечивать
непересечение некоторых других пар. Поэтому найденная расстановка — лишь
решение текущей релаксации. Скрипт находит все реальные столкновения на
полной жизни труб и добавляет для этих пар точные дизъюнкции. Затем решает
усиленную модель. Никакой статус FEASIBLE релаксации не объявляется успехом
исходной задачи.

UNKNOWN не превращается в доказательство несовместимости: он вызывает
смену поискового режима и при повторении — снятие дополнительных связей.

## Сохранение нагрузки во время обменов

По умолчанию добавлены ограничения загрузки во времена
`9810,9818,9831,9837`. В каждый такой момент префикс разбивает высоту на
реальные свободные слоты `[a_k,b_k)`. Каждая активная суффиксная труба
выбирает ровно один подходящий слот:

```
sum_k x_ik = 1
x_ik => a_k <= y_i AND y_i + len_i <= b_k
load_k = sum_i len_i*x_ik
capacity_k - S(t) <= load_k <= capacity_k
S(t) = H - sum(length of every live pipe at t)
```

Все временные строки используют **одну и ту же переменную y_i**. Это
не набор независимых пиковых упаковок.

В t9818 `S(t)=1`, поэтому резерв любого слота не превышает одного метра.
Во времена 9810 и 9831 ограничения учитывают нагрузку верхнего коридора406
при целевой ёмкости399. Вытесненные трубы не исчезают из суммы, как в
старой эжекционной релаксации.

Эти ограничения необходимы, но сами по себе ещё не исключают все
пересечения внутри слота. Точное непересечение обеспечивается добавлением
парных ограничений и окончательным валидатором.

## Размер модели и остановка

По умолчанию:

- `cp_model_presolve=False`, probing и symmetry отключены.
- Явных обратимых пар не более `--max-disjunctions 12000` в модели решателя.
- Сразу не строятся сотни тысяч попарных дизъюнкций.
- В режиме извлечения ядер используется один поток; обычный поиск
  использует указанное число `--workers`.
- Каждый запуск идёт в отдельном дочернем процессе. Родительский watchdog
  ограничивает его время с небольшим запасом на запуск и завершение.
- `--seconds` ограничивает весь поиск приблизительно: возможны накладные
  расходы на завершение текущего процесса и сохранение состояния.
- При исчерпании лимита пар скрипт сохраняет checkpoint и завершается,
  а не объявляет задачу неразрешимой.

Отключение presolve устраняет зависание именно в этой фазе. Оно не
гарантирует быстрого поиска решения. Дополнительные ограничения порядка
тоже остаются эвристикой: даже при существовании плана нужные связи могут
не быть освобождены за отведённый бюджет.

## Запуск вручную

Решатель не запускается автоматически при открытии файла. На занятой
машине число потоков следует выбрать самостоятельно. Пример на 2 потока:

```powershell
Set-Location D:\techarena2026
$py = 'C:\Users\gudil\AppData\Local\Programs\Python\Python310\python.exe'
& $py bench\solve_test11_lazy.py --workers 2 --seconds 7200 --slice 30
```

Когда машина свободна, можно указать `--workers 16`. База по умолчанию —
`target/test11-freed4.txt`; при её отсутствии берётся `test11-resume.txt`.
Лучшие входные планы не перезаписываются.

При успехе появится только прошедший полную проверку файл:

```
target/test11-candidate-20760.txt
```

Перед записью проверяются число координат, неотрицательность, точное
равенство префикса, отсутствие коллизий на всех командах и сырая высота
не более запрошенной. Запись производится через временный файл.

Штатная остановка: **Ctrl+C**. Можно также создать stop-файл из другого
PowerShell; родитель завершит свой дочерний решатель и сохранит состояние:

```powershell
New-Item -ItemType File -Path D:\techarena2026\target\test11-lazy.stop -Force
```

Пока этот файл существует, новый поиск не стартует. Перед намеренным
повторным запуском его следует удалить:

```powershell
Remove-Item -LiteralPath D:\techarena2026\target\test11-lazy.stop
```

Продолжение сохранённого поиска:

```powershell
& $py bench\solve_test11_lazy.py --workers 2 --seconds 7200 --resume target/test11-lazy-state.json
```

Checkpoint — это **состояние поиска, не допустимый план**. Он сохраняет
освобождённые связи, найденные ограничения и подсказку координат.

Коды завершения: `0` — проверенный целевой план; `1` — бюджет/лимит;
`2` — доказанная несовместимость необходимой релаксации;
`3` — ошибка модели/процесса; `130` — штатная остановка.

## Разумные варианты развития

1. Если парные ограничения растут быстро, попробовать локальные временные
   клики `--local-cliques 100`: все трубы в такой клике активны одновременно,
   поэтому NoOverlap1D корректен даже при их последующем перемещении.
2. Не включать глобальные клики на все525пиковых труб без сравнения:
   короткие пробы такого варианта были существенно тяжелее.
3. При застревании менять приоритет снятия связей внутри UNSAT-ядер;
   освобождать отношения, а не задавать новые неподвижные границы по y/t.
4. Сравнить цель суммы смещений с числом смен слота: первая удерживает
   поиск около базы, но может чрезмерно штрафовать необходимые переносы
   между далёкими коридорами. `--no-anchor` убирает эту цель.
5. Пробовать другие обязательные строки времени через `--capacity-times`;
   геометрия каждого слота вычисляется заново из префикса на выбранный t.

Гарантируется проверка допустимости сохраняемого результата. Нахождение
H20760 за 1–2 часа этим решателем пока не подтверждено.
